# Astra 공개 데모 조사와 Afterglow의 다음 방향

조사일: 2026-09-06, 한국 시간. 범위: 9월 3일 발표 전후에 공개된 데모, 제작자 발언, 시연 방송과 초기 사용자 반응. 이 문서는 방향 제안이며 제품 구현이나 공개 배포 완료 기록이 아니다. 추가 스킬과 하위 에이전트는 사용하지 않았다.

추천하는 다음 방향은 **손끝의 움직임이 꽃과 빛의 성격으로 남는, 30초짜리 작은 하늘**이다. 사용자가 만든 하늘을 다른 사람도 같은 모습으로 열어 볼 수 있게 연결한다. 현재의 절제된 선화, Night Sky / Paper Sky, 짧은 휴식과 모바일 성능을 중심에 둔다.

## 조사 방법과 근거의 범위

공식 발표, 출시 데모 모음 두 곳, 공개 저장소, 제작자가 참여한 시연 방송, 초기 사용자 토론을 교차 확인했다. 아래 아홉 사례는 관련성이 높은 표본이다. 공식 영상의 재게시를 독립 제작 사례로 세지 않았고, 검색 결과의 좋아요·조회 수는 현재 원본에서 검증하지 못했으므로 순위를 매기지 않았다. 따라서 여기서 말하는 반응은 공개된 정성적 반응이며 전체 이용자의 여론이나 바이럴의 인과관계를 측정한 결과는 아니다.

확인 수준은 다음과 같이 구분했다.

- **직접 실행:** Van Gogh Town의 침실과 마을 전체 시점 전환, ABYSSAL의 수면 진입과 산호초 하강을 브라우저에서 조작하고 화면을 확인했다. 데스크톱 브라우저에서의 짧은 탐색이며, 모든 기능이나 모바일 성능을 검증한 것은 아니다.
- **공개 코드 확인:** ABYSSAL 저장소의 README와 `AnimalMotion.js`를 읽었다. 저장소의 현재 구현은 출시 당시 첫 생성물과 같다고 가정하지 않았다.
- **발언 확인:** ThursdAI의 공개 시연 전사와 Reddit의 사용자 댓글을 읽었다. 이는 당사자 경험이나 의견이며 통제 실험이 아니다.
- **자료를 통한 확인:** 일부 X 원문은 웹 도구에서 403, YouTube 원본은 429를 반환했다. 브라우저의 YouTube 전사도 제공되지 않았다. 해당 사례의 제작 시간·도구·프롬프트 횟수는 공개 소개 자료의 전언으로만 취급한다. 원본 영상을 전부 시청했거나 제작 과정을 재현했다고 주장하지 않는다.

## 사람들이 놀라는 강점과 그 한계

**1. 특정한 시각 언어를 끝까지 유지하는 능력.** 직접 본 Van Gogh Town에서는 바닥, 가구, 하늘을 연결하는 붓질이 인상적이었다. Afterglow에서도 꽃, 포인터, 입자와 전환이 같은 표현 원리를 공유할 때 정체성이 강해질 것으로 판단한다. [Van Gogh Town](https://van-goghs-town.surge.sh/)

**2. 만져 보면 안쪽까지 작동한다는 발견.** macOS 시연의 놀라움은 메뉴·창·앱을 계속 확인하는 장면에서 나왔다. 다만 Gostev는 별도의 게임 예시에 대해 “very polished but boring”이라고 말했다. 작동하는 것, 정교한 것, 재미있는 것을 따로 검증해야 한다. [ThursdAI 시연 전사](https://thursdai.news/ep/astra)

**3. 화면을 해석하며 긴 작업을 이어가는 능력.** 공식 설명은 스스로 화면을 확인하는 QA, 여러 단계의 제작과 요구 변경의 반영을 강조한다. 이는 Afterglow의 개발 방법에 적용할 만하다. 제품에 실시간 모델 호출을 추가해야 한다는 근거는 아니다. [OpenAI 발표](https://openai.com/index/gpt-6-astra/)

**4. 세부 행동들이 모여 생기는 생동감.** ABYSSAL의 공개 동작 코드에는 관성, 이웃 간 간격, 장애물 회피, 고정 간격의 시뮬레이션과 화면 보간이 있다. 내 판단으로는 Afterglow도 가까운 꽃 몇 개의 일관된 반응만으로 생동감을 크게 높일 수 있다. [AnimalMotion.js](https://github.com/emollick/abyssal-living-deep/blob/main/src/underwater/AnimalMotion.js)

초기 사용자의 반응은 일치하지 않는다. 브라우저 게임이 이전보다 제대로 동작한다는 후기가 있는 반면, 프런트엔드는 구체적인 예시 없이 맡기면 상투적이라는 의견도 있다. 작은 익명 표본이지만, 모델 이름만으로 디자인 품질을 보장할 수 없다는 반례로는 유효하다. ## 권장 작업 순서

### 1. 손끝과 꽃 사이의 반응을 먼저 만든다

포인터 주변 최대 4~6개의 꽃이 진행 방향으로 살짝 기울고 돌아온다. 빠른 움직임은 짧은 파문, 느린 움직임은 부드러운 열림으로 표현한다. 어느 속도도 점수나 보상 우위로 만들지 않는다. 손을 멈춰도 현재의 천천한 수집은 유지한다.

꽃 생성 시 입력 방향과 최근 곡률을 형태에 조금 반영하고, 제한된 난수로 다양성을 보탠다. 이 변화는 정확히 따라 그리는 기능보다 손길의 흔적을 남기는 데 목적이 있다. 정지 화면에서도 다른 두 사람의 결과가 구별되는지 확인한다.

작은 입자만 늘리기보다 가는 곡선, 중심과 바깥 꽃잎의 깊이 차이, 연결선의 굽음을 먼저 실험한다. 화면 전체의 시차 이동 없이도 개별 오브젝트의 깊이를 표현할 수 있다.

### 2. 30초의 시작·성장·끝을 연결한다

첫 입력이 가까운 한 개의 loose thought에 반응하도록 해 첫 수집의 원인을 읽기 쉽게 한다. 중간에는 사용자가 만든 꽃과 연결의 관계가 점차 드러나게 한다. 마지막 실제 수집의 반응이 가라앉은 뒤 짧게 작품 전체를 보여주고 현재 결과 화면으로 이어진다. 가상의 꽃을 자동으로 더하거나 사용자의 배치를 임의의 예쁜 구도로 바꾸지 않는다.

Night Sky는 얇은 발광 선과 궤도, Paper Sky는 색연필이나 얇은 종이를 떠올리게 하는 선과 굽음을 탐색한다. 색은 기존 토큰을 유지한다. 사진 같은 종이 질감이나 전면 노이즈를 추가하는 방향은 피한다.

### 3. 같은 작품을 열 수 있는 공유를 만든다

현재 모바일 PNG는 이미 플레이 화면 비율을 유지한다. 다음에는 정규화한 꽃 위치·형태·색·장면을 제한된 크기의 작품 데이터로 저장해 링크에서 복원한다. 난수 seed만으로는 사용자의 수집 위치와 움직임이 복원되지 않으므로 최종 작품 상태가 필요하다.

받는 사람은 작품을 먼저 보고 자신의 30초를 시작할 수 있다. PNG와 작품 링크가 같은 하늘을 나타내는지 확인한다. 짧은 재생이나 영상 저장은 이후 후보로 둔다. 자동 녹화·자동 재생으로 매 방문의 GPU 작업을 늘리지 않는다.

### 4. 반복 검증으로 완성도를 높인다

같은 입력과 seed를 재현할 수 있는 개발용 장면을 두고, 동작·화질·프레임을 비교한다. 화면을 수정할 때마다 시작·첫 수집·꽃이 많이 모인 순간·종료·세로 저장까지 확인한다. Astra의 시각 확인과 긴 작업 수행 능력을 이 반복 과정에 사용한다.

## 모바일 성능을 지키는 구현 기준

ABYSSAL 저장소 자체도 데스크톱 그래픽을 권장하며 휴대폰 성능을 보장하지 않는다. 따라서 그 데모의 광학 효과나 렌더 파이프라인을 Afterglow에 그대로 가져올 이유는 없다. [ABYSSAL 실행 환경 안내](https://github.com/emollick/abyssal-living-deep)

이 프로젝트에 제안하는 기준은 다음과 같다.

- 화면 출력은 현재의 60fps 시작·실측 90/120fps 승격 정책을 유지한다. 생태적 반응 계산은 화면 출력과 분리하고 보간하는 방식을 검토한다. 논리 계산 빈도와 화면 프레임 제한을 혼동하지 않는다.
- 각 꽃의 매 프레임 geometry 재생성을 피하고, 공용 geometry·변환·소수의 파라미터로 표현한다. 가까운 꽃의 반응 대상 수도 제한한다.
- 현재의 한 개 drawing surface, 모바일 150만 픽셀 상한, 해상도 우선 조절, 숨김·일시정지·결과의 렌더 중단을 유지한다.
- 입력·수집·저장 결과는 기기 품질 단계에 따라 달라지지 않아야 한다. 낮은 품질에서도 같은 작품을 만든다.
- S24 일반 모드와 데스크톱 사이트 모드에서 반복 플레이, 화면 회전, 백그라운드 복귀를 비교한다. 프레임 간격·CPU/GPU 시간·품질 단계·메모리 증가와 확보 가능한 열 상태를 기록한다. 실기기 온도 검증은 현재 미완료다.

## 첫 개선 묶음의 합격 기준

아래 항목은 앞으로 검증할 목표이며 아직 얻은 결과가 아니다.

| 항목 | 확인할 것 |
| --- | --- |
| 첫인상 | 설명을 읽지 않은 사용자도 첫 수집과 자신의 동작 사이의 관계를 말할 수 있다. |
| 손맛 | 느린 이동·빠른 이동·멈춤의 피드백이 구별되고 작은 터치 화면에서도 조작을 방해하지 않는다. |
| 작품성 | 같은 수집 수라도 서로 다른 움직임의 결과가 구별된다. |
| 재현 | 동일 작품 데이터가 다른 화면 비율에서도 같은 꽃과 연결 관계로 복원된다. |
| 공유 | PNG와 링크가 같은 작품을 가리키며, 받는 사람이 새 작품 만들기로 이어갈 수 있다. |
| 성능 | 기존 버전 대비 CPU/GPU 비용과 장시간 프레임 저하를 비교한다. 자동 검사 통과를 열 검증 완료로 대신하지 않는다. |
| 접근성 | reduced motion·일시정지·키보드·Canvas fallback에서도 수집과 저장이 유지된다. |

첫 구현 범위로는 **포인터 주변 꽃의 반응 → 입력 흔적을 반영한 꽃 형태 → 짧은 완성 장면**을 권한다. 이 묶음이 재미와 성능을 함께 통과하면 작품 링크를 연결한다. 대형 3D 월드, 실시간 LLM 캐릭터, 전면 후처리는 이번 방향의 필수 요소가 아니다.
