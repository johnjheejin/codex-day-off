# ADR-0001: 프로젝트 범위 oh-my-design 파일럿 적용

- 상태: 승인 및 적용
- 결정일: 2026-06-20
- 적용 대상: Afterglow — Codex's Day Off
- 최초 도입 도구: `oh-my-design-cli@1.8.2`
- 원본: <https://github.com/kwakseongjae/oh-my-design>

## 맥락

이 프로젝트는 별도의 빌드 단계나 프레임워크 없이 `index.html` 하나로 실행되는 30초 인터랙티브 웹 경험이다. 프로젝트 루트의 `DESIGN.md`에 색상, 타이포그래피, 레이아웃, 모션, 보이스와 금지 패턴이 이미 정의되어 있다.

현재 디자인은 Open Design 계열의 핵심 방식인 다음 특성을 이미 갖고 있다.

- 디자인 결정을 코드 밖의 읽을 수 있는 명세로 유지한다.
- 토큰뿐 아니라 제품 철학, 보이스와 모션 원칙을 함께 정의한다.
- AI 코딩 에이전트가 동일한 명세를 반복해서 사용할 수 있다.

따라서 새로운 회사 레퍼런스를 기반으로 디자인 시스템을 다시 생성하는 것보다, 현재 `DESIGN.md`를 Codex 작업과 리뷰 과정의 권위 있는 기준으로 연결하는 것이 목적에 맞다.

## 결정

`oh-my-design`을 전체 환경이나 모든 프로젝트에 설치하지 않고 이 저장소에만 파일럿으로 적용한다.

다음 네 개의 Codex 스킬만 프로젝트 로컬 경로인 `.agents/skills/`에 설치한다.

1. `omd-apply`: UI 변경 전에 `DESIGN.md`를 읽고 디자인 맥락을 적용
2. `omd-designer-review`: 구현 결과를 디자인 명세와 비교하여 읽기 전용 리뷰
3. `omd-final-qa`: 배포 전 브랜드, 접근성, 반응형과 품질 기준 점검
4. `omd-sync`: `DESIGN.md`가 에이전트 지침에 연결된 상태인지 관리

`AGENTS.md`에는 UI, 카피, 스타일과 모션 작업 전에 `DESIGN.md`를 전체 읽도록 하는 OmD 관리 블록을 추가한다.

## 안전 범위

다음 항목은 이번 파일럿에서 제외한다.

- 글로벌 설치
- Claude Code, Cursor, OpenCode 채널 설치
- `--force` 옵션
- OmD 서브에이전트
- Claude 훅과 설정 파일
- 286개 디자인 레퍼런스 카탈로그
- OmD 데이터 파일
- `omd:init`

특히 `omd:init`은 기존 `DESIGN.md`를 `DESIGN_DEPRECATED.md`로 이동하고 레퍼런스 기반의 새 명세를 생성할 수 있으므로 이 프로젝트에서는 사용하지 않는다.

## 판단 근거

### 기대 효과

- 현재 디자인 원칙을 UI 변경 때마다 다시 설명할 필요가 줄어든다.
- 리뷰 결과가 개인적 취향 대신 저장소에 기록된 명세를 근거로 삼게 된다.
- 디자인 리뷰와 최종 QA를 읽기 전용으로 수행할 수 있다.
- 프로젝트 로컬 파일만 삭제하면 원래 상태로 복구할 수 있다.

### 확인된 위험

| 위험 | 파일럿에서의 가능성 | 영향 | 대응 |
|---|---:|---:|---|
| 제3자 npm 코드 실행 | 낮음 | 큼 | 버전을 `1.8.2`로 고정하고 공개 소스의 설치 및 postinstall 코드를 검토 |
| 기존 파일 덮어쓰기 | 매우 낮음 | 중간 | `--force`를 사용하지 않고 관리 마커 없는 파일은 건너뛰는 설치 방식 사용 |
| 기존 디자인 시스템 교체 | 낮음 | 큼 | `omd:init`을 설치·실행 범위에서 제외 |
| 저장소 파일 증가 | 낮음 | 낮음 | 네 개의 단일 파일 스킬만 설치하고 데이터·레퍼런스·에이전트 제외 |
| 스킬 지침의 과도한 자동화 | 낮음 | 중간 | 디자인 변경은 기존 사용자 요청 범위 안에서만 수행하고 리뷰 스킬은 읽기 전용으로 사용 |

이번 제한 구성의 종합 위험은 낮음, 약 2/10으로 판단한다. 전체 스킬·레퍼런스·서브에이전트 설치보다 기능은 제한되지만 현재 프로젝트의 규모와 파일럿 목적에는 적절하다.

## 적용 결과

추가된 관리 대상:

- `.agents/skills/omd-apply/SKILL.md`
- `.agents/skills/omd-designer-review/SKILL.md`
- `.agents/skills/omd-final-qa/SKILL.md`
- `.agents/skills/omd-sync/SKILL.md`
- `AGENTS.md`

변경하지 않은 핵심 파일:

- `DESIGN.md`
- `index.html`
- `README.md`

## 성공 기준

다음 조건을 실제 디자인 작업에서 확인한 뒤 확대 적용을 검토한다.

1. Codex가 UI 변경 전에 `DESIGN.md`를 일관되게 읽는다.
2. 제안과 구현이 기존 색상, 타이포그래피, 모션과 보이스 원칙을 위반하지 않는다.
3. 디자인 리뷰가 구체적인 파일 위치와 근거를 제공한다.
4. 스킬로 인한 불필요한 파일 변경이나 작업 지연이 크지 않다.
5. 기존 수동 작업보다 디자인 일관성과 검수 효율이 개선된다.

## 2026-07-11 중간 평가

파일럿은 **이 프로젝트 안에서 계속 사용할 가치가 있음**으로 평가한다.

- UI 변경 전에 `DESIGN.md`를 다시 읽는 절차가 실제로 작동했다.
- `omd:designer-review`와 `omd:final-qa`의 형식을 사용해 기존 구현을 재검수했다.
- 6월 검수에서 통과했던 화면을 다시 확인하면서 숨겨진 결과 화면과 HUD의 접근성 상태가 시각 상태와 동기화되지 않는 문제를 발견했다.
- 수정은 `aria-hidden`, `inert`, 명시적 포커스 이동, reduced-motion 대응과 결과 배경 대비 조정으로 제한했다.
- 390×844 실제 브라우저 흐름에서 시작, 30초 플레이, 결과, 여섯 개 공유 버튼과 LinkedIn 안내창을 확인했다.

다만 이 결과는 Ponytail이나 Open Design 구현을 직접 설치했다는 뜻이 아니다. 두 프로젝트를 검토하며 채택한 것은 디자인 결정을 코드 밖에 기록하고 에이전트가 동일한 명세를 반복 적용한다는 운영 방식이다. 실제 설치 대상은 프로젝트 로컬 `oh-my-design` 스킬 네 개뿐이다.

현재 결론은 프로젝트 로컬 파일럿 유지다. 다른 프로젝트나 전역 환경으로 확대할 근거는 아직 충분하지 않다.

## 2026-07-13 최신 흐름 재평가

공식 문서 기준 최신 OmD는 `v1.8.8`이며 18개 스킬, 16개 전문 에이전트, 400개 레퍼런스와 10단계 harness를 제공한다. 이 저장소의 네 개 스킬 구성은 **최신 전체 설치가 아니라 의도적으로 제한한 부분 적용**이다.

이번 `Night Sky / Paper Sky`와 Galaxy S24 공유 동선 수정에서 확인한 내용:

- `omd:apply`가 `DESIGN.md`를 먼저 적용하고 모바일 UX 작업을 전문 검토 경로로 분류했다.
- 사용자 교정이 제품 코드뿐 아니라 `DESIGN.md`, README와 런타임 가드에 함께 반영됐다.
- `omd:sync` 규칙에 따라 세 shim의 관리 본문을 보존하고 `DESIGN.md` 해시를 갱신했다.
- 360×720 결과 화면에서 공유 기본 행동과 여섯 목적지, 세로 스크롤과 두 장면의 대비를 실제 브라우저로 확인했다.

따라서 핵심 루프인 **명세 → 구현 → 반응형 검증 → 명세 동기화**는 작동한다. 다만 최신 `omd:apply`가 참조하는 `omd-ux-engineer`, `omd:feel`, `omd:remember`, 접근성 전문 에이전트와 공식 hooks는 이 저장소에 없다. 이번 작업에서는 Codex의 일반 서브에이전트가 UX 검토 역할을 대신했으므로, 현재 구성은 동작하지만 공식 `v1.8.8` 전체 topology와 같다고 표현하면 안 된다.

현재 프로젝트는 단일 HTML이고 고유한 `DESIGN.md`가 이미 성숙해 있다. 18개 스킬과 400개 레퍼런스를 곧바로 전부 설치하면 기능보다 관리 표면이 더 크게 늘 수 있으므로 자동 확대하지 않는다. 전체 프로젝트 로컬 업그레이드는 사용자가 명시적으로 선택할 때 별도 변경으로 수행한다.

- 공식 문서: <https://oh-my-design.kr/docs>
- 확인한 문서 버전: `v1.8.8`

## Ponytail 재평가

Ponytail 최신 릴리스는 `v4.8.4`이며 Codex plugin과 `AGENTS.md` 기반 instruction-only 흐름을 지원한다. 핵심은 YAGNI → 기존 코드 재사용 → 표준·네이티브 기능 → 이미 설치된 의존성 → 최소 구현 순서로 과설계를 억제하는 것이다.

Ponytail plugin이나 hooks는 이 저장소와 현재 Codex 환경에 설치하지 않았다. 대신 이번 수정은 기존 장면 버튼과 결과 패널을 재사용하고, 새 프레임워크·렌더러·공유 라이브러리 없이 DOM 순서와 CSS 스크롤 규칙만 고쳤다는 점에서 그 최소 구현 원칙과 일치한다.

Ponytail 설치는 제품 런타임 기능이 아니라 이후 에이전트의 코딩 방식을 바꾸고 Codex 재시작과 hook 신뢰가 필요한 운영 변경이다. 사용자의 명시적 승인 없이 자동 설치하지 않는다.

- 원본 및 Codex 설치 흐름: <https://github.com/DietrichGebert/ponytail>
- 확인한 최신 릴리스: <https://github.com/DietrichGebert/ponytail/releases/tag/v4.8.4>

## 확대 조건

파일럿이 성공하면 다음 순서로 범위를 넓힌다.

1. 이 프로젝트에서 필요한 추가 OmD 스킬만 선택 설치
2. 비슷한 디자인 중심 프로젝트 한 곳에 프로젝트 로컬로 추가 적용
3. 두 개 이상의 프로젝트에서 효과와 부작용이 재현될 때만 글로벌 설치 검토

글로벌 설치는 기본 선택이 아니며, 프로젝트별 디자인 시스템 간 충돌과 에이전트 지침 우선순위를 별도로 검토한 뒤 결정한다.

## 롤백

파일럿을 중단할 경우 다음 항목만 제거한다.

- `.agents/skills/omd-apply/`
- `.agents/skills/omd-designer-review/`
- `.agents/skills/omd-final-qa/`
- `.agents/skills/omd-sync/`
- `AGENTS.md`의 `omd:start`와 `omd:end` 사이 관리 블록

이 롤백은 제품 코드와 기존 `DESIGN.md`에 영향을 주지 않는다.
