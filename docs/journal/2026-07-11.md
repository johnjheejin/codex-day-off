# 2026-07-11 — Afterglow를 다시 바라본 날

Afterglow는 Codex 밋업을 위해 짧게 만든 데모에서 멈추지 않았다. 오늘 다시 열어 본 프로젝트는 GitHub, Cloudflare Pages, 모바일 조작, 결과 이미지와 소셜 공유까지 갖춘 작은 제품에 가까웠다. `main`과 `origin/main`은 `b301be2`로 일치했고, 공개 사이트는 최신 `index.html`을 제공하고 있었다.

## 오늘의 시점

2026년 7월 11일은 이 프로젝트를 다시 보는 데 묘하게 적절한 날이었다. OpenAI는 7월 9일 GPT-5.6 계열을 정식 공개하며 Sol을 플래그십 모델로 소개했다. Anthropic은 중단됐던 Claude Fable 5 접근을 7월 1일 복구했고, 7월 12일 밤부터 일반 구독의 포함 사용을 추가 종량 과금으로 전환할 예정이라고 보도됐다.

- OpenAI: <https://openai.com/index/gpt-5-6/>
- Anthropic: <https://www.anthropic.com/claude/fable>
- 7월 12일 과금 전환 보도: <https://www.wired.com/story/model-behavior-anthropic-will-charge-consumers-extra-to-use-claude-fable-5/>

레포 주인의 관점에서 보면, 최고 성능의 코딩 모델들이 재출시·확대·과금 전환을 두고 맞붙는 바로 그 사이에 오래된 Codex 프로젝트를 최신 Sol로 다시 검수하는 장면 자체가 흥미롭다. 이 문장은 제품의 객관적 기능 명세가 아니라 2026년 7월 11일에 이 저장소를 다시 연 사람의 시점 기록이다.

## Ponytail과 Open Design은 실제로 어떻게 적용됐나

처음 기대는 Ponytail과 Open Design 같은 접근을 활용해 프로젝트의 디자인 품질을 끌어올리는 것이었다. 확인 결과 두 프로젝트의 코드나 패키지가 Afterglow에 직접 들어간 것은 아니다.

대신 Open Design 계열에서 중요하게 본 운영 방식이 적용됐다.

- 디자인 원칙을 `DESIGN.md`에 코드와 분리해 기록한다.
- 색상뿐 아니라 보이스, 모션, 레이아웃과 금지 패턴까지 같은 명세에 둔다.
- UI를 바꾸기 전에 에이전트가 명세를 다시 읽는다.
- 구현 뒤에는 같은 명세로 디자인 리뷰와 최종 QA를 수행한다.

이를 위해 프로젝트 로컬에 `oh-my-design` 스킬 네 개만 설치했다. 전역 설치, 레퍼런스 카탈로그, 자동 초기화와 서브에이전트는 제외했다. 즉 Ponytail을 제품에 이식한 것이 아니라, 관련 검토에서 얻은 디자인 운영 원리를 작은 저장소에 맞게 축소 적용한 셈이다.

## 오늘 직접 확인한 구현 상태

잘 완성된 부분:

- 설치나 로그인 없이 열리는 단일 HTML 경험
- 마우스, 방향키/WASD와 모바일 터치 조작
- 30초 동안 수집한 위치를 보존하는 결과 장면
- 1200×630 PNG 생성과 네트워크별 정직한 공유 안내
- 데스크톱과 390×844 모바일에서 가로 넘침 없는 반응형 구성
- 모바일 결과 화면에서 여섯 개 공유 버튼을 모두 유지
- 차분한 흰색 시작 화면과 이벤트 컬러가 나타나는 밤 장면의 대비
- Afterglow 워드마크와 해질녘 심볼, 일관된 “loose thoughts” 보이스

아쉬웠던 부분:

- 시각적으로 숨긴 결과 화면과 HUD가 접근성 상태와 완전히 동기화되지 않았다.
- 플레이 시작과 종료 때 키보드 포커스가 경험의 현재 위치를 따라가지 않았다.
- 모션 감소 환경을 별도로 존중하지 않았다.
- 모바일 결과 화면에서 별자리 군집이 공유 정보 뒤로 강하게 겹쳐 가독성을 침범했다.
- GitHub About 설명은 아직 “60-second”라고 적혀 실제 30초 제품과 다르다.
- `afterglow-static-html.zip`은 6월 18일 구버전이라 현재 제출 번들로 사용할 수 없다.

## 오늘 개선한 것

- 숨겨진 결과 화면에 `aria-hidden`과 `inert`를 적용했다.
- HUD의 접근성 노출을 플레이 상태와 동기화했다.
- 플레이 시작 시 캔버스, 종료 시 결과 제목으로 포커스를 이동했다.
- 캔버스에 키보드 조작을 설명하는 접근 가능한 이름을 부여했다.
- `prefers-reduced-motion`에서 장식적 전환, 별 반짝임과 꽃의 회전·맥동을 줄였다.
- 결과 화면의 캔버스 불투명도를 낮춰 공유 정보의 위계를 회복했다. 내보내는 PNG의 장면은 그대로 유지했다.

## 다음 연장선

1. GitHub About의 60초 설명을 30초로 수정한다.
2. 최신 파일로 정적 HTML ZIP을 다시 만들고 내용과 해시를 검증한다.
3. 실제 iPhone Safari와 Android Chrome에서 터치, 다운로드와 네이티브 공유를 확인한다.
4. 영문 경험을 유지할지, 한국 밋업의 맥락을 담은 한국어 진입점 또는 프로젝트 회고 페이지를 추가할지 결정한다.
5. Afterglow를 일회성 출품작이 아니라 “Codex와 함께 계속 돌보는 작은 제품”으로 남길 최소 유지 주기를 정한다.

오늘의 결론은 전면 재설계가 필요하다는 것이 아니다. 핵심 콘셉트와 디자인은 이미 선명하다. 앞으로의 완성도는 더 많은 장식을 더하는 것보다, 접근성·실기기 검증·배포 산출물·프로젝트 기록을 꾸준히 맞추는 데서 올라갈 가능성이 크다.

## 이 기록을 밖으로 꺼내기

이 일지는 내부 회고로만 남기지 않는다. 결과 화면에는 30초 경험을 마친 사람만 발견할 수 있는 프로젝트 노트를 연결하고, README에는 제작부터 재검수까지의 연대기를 둔다. 레포 주인이 자신의 목소리로 이 에피소드를 소개할 수 있도록 LinkedIn 초안도 `docs/social/linkedin-2026-07-11.md`에 함께 남겼다.

중요한 것은 모델 경쟁을 구경거리로만 소비하는 것이 아니다. 빠르게 바뀌는 도구 사이에서도 이미 만든 프로젝트에 다시 관심을 주고, 이전 판단을 검증하고, 작은 결함을 고치며, 그 과정을 공개된 기록으로 남길 수 있다는 점이 이 에피소드의 본체다.
