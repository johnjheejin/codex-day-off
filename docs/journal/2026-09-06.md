# 2026-09-06 — 저장한 하늘이 다시 움직인다면

Afterglow를 다시 열게 한 말은 “대 GPT-6 Astra 시대에 맞춰서”였다. 이미 공개된 30초짜리 휴식 경험에 Three.js를 더하고, 지금 쓰는 도구로 어디까지 완성도를 높일 수 있는지 보고 싶다는 요청이었다. 이번 작업은 GPT-6 Astra와 진행했고, 사용자의 요청에 따라 추가 스킬이나 하위 에이전트는 쓰지 않았다.

새 모델의 이름을 붙이는 것만으로는 이 프로젝트를 다시 열 이유가 되지 않는다. 이번에 가장 유용했던 기준은 사용자가 실제로 여러 번 플레이한 뒤 남긴 말들이었다.

## 놀라는 순간을 우리 경험으로 가져오기

먼저 웹에서 공유되는 Astra 데모를 살펴봤다. 화면을 직접 조작할 수 있는 사례는 브라우저로 열어 보고, 원문이나 전사에 접근할 수 없는 사례는 확인 범위를 구분했다. [조사 기록](../research/2026-09-06-astra-demo-directions.md)은 아홉 사례와 근거의 한계를 함께 남긴다.

그 조사에서 Afterglow에 가져온 방향은 손길이 결과에 남는다는 것이었다. 마우스나 손가락의 방향, 속도, 굽이침과 잠깐의 멈춤이 꽃의 길이와 곡선, 꽃잎에 반영된다. 주변 꽃은 가까이 지나가는 손길에 기울었다가 돌아온다. 많이 모으거나 빨리 움직여야 좋은 결과를 얻는 규칙은 추가하지 않았다.

30초가 끝나면 잠깐 하늘만 남는다. 막 만들어진 꽃이 피는 것을 보고 나서 결과로 넘어간다. 휴식이 끝났다는 사실을 곧바로 공유 버튼으로 덮지 않기 위한 작은 간격이다.

## “딱 봐도 Codex로 한 것”을 넘어서

사용자는 메인의 `Close the tabs. Open the sky.` 타이포그래피도 다시 봐 달라고 했다. AI로 만들었다는 인상을 지우는 문제가 아니라, 그 자체로 디자인 완성도가 높은지 묻는 피드백이었다.

큰 산세리프 문장 두 개가 반복되던 첫 화면을 작은 도입과 Newsreader 세리프 초대로 나눴다. 채팅 입력창처럼 보이던 시작 영역에는 명확한 버튼을 두었다. 이후 결과 제목, 일시정지, 공유 안내와 PNG의 글자까지 같은 위계로 검토했다. 모바일의 작은 화면에서는 꽃과 글자가 경쟁하지 않도록 줄바꿈과 여백을 따로 확인했다.

Paper Sky에 검은 덩어리처럼 보이던 수집 대상은 옅은 색 선과 작은 빛으로 교정했다. 모바일에서 만든 결과는 모바일 화면 비율로 저장되며, 저장 뒤 화면을 돌려도 원래 비율을 유지한다. 이미지 전달을 지원하지 않는 앱에는 PNG를 직접 첨부해야 한다는 설명을 먼저 보여 준다.

## 이미지를 남기는 것 다음에

공개본을 여러 번 해 본 뒤 다음 아이디어가 나왔다.

> 만들어지고 난 나만의 스카이가 살아있는 느낌

완성 이미지를 크게 보여 주는 기능은 이미 있었다. 여기에 손으로 비비거나 마우스로 지나가면 꽃이 살랑거리는 보기, 그리고 시선을 바꾸어 하늘을 돌려 보는 기능이 더해졌다.

처음에는 결과의 Explore sky를 눌러 라이브 보기에 들어가도록 만들었다. 이어진 피드백에서는 그 하늘에 계속 머물고 싶다는 요청이 나왔다. 이제 30초가 끝나면 꽃과 별자리 연결이 그대로 남는다. **Touch**는 가까운 꽃을 움직이고, **Turn**은 드래그로 꽃과 연결선 전체의 방향을 바꾼다. 각 꽃의 입체 곡선과 얕은 깊이 차이가 다른 각도에서 드러난다. 방향키로도 조작할 수 있고 **Reset**으로 정면으로 돌아온다.

돌려 본 각도와 손길 반응은 별도 보기 상태에만 남긴다. 원래 작품의 구도와 다운로드 PNG는 유지한다. 현재 라이브 뷰는 완료한 페이지 안에서 이용하며, 새로고침 뒤 같은 하늘을 복원하거나 타인에게 움직이는 하늘 링크를 보내는 기능은 아직 없다.

소리는 이제 기본으로 켜진다. 시작 버튼을 누른 뒤 꽃을 모을 때 짧은 음이 들리며, 사용자가 음소거하면 이후 방문에도 기억한다. 이전 버전은 기본 음소거까지 저장해 사용자의 직접 선택과 구분할 수 없었다. 이번에는 첫 방문 기본값을 새로 적용하고, 실제 소리 버튼 선택만 저장한다.

## 살아 있는 동안만 일하기

모바일 발열 이력은 계속 중요한 제약이다. Galaxy S24에서 데스크톱 사이트 모드가 큰 렌더 버퍼를 만드는 문제가 있었고, 이후 터치 하드웨어 감지와 픽셀 예산을 따로 두었다. Three.js를 넣었다고 이 제약이 사라지지는 않는다.

플레이는 60fps부터 시작하고 측정된 여유가 있을 때 90/120Hz 화면을 활용한다. 부하가 지속되면 내부 해상도를 먼저 조정한다. 라이브 뷰는 입력과 짧은 복귀 움직임 동안 최대 60fps로 그린다. 꽃이 가라앉으면 렌더링도 멈춘다. 숨긴 페이지에서는 멈추고, 모션 줄이기 환경에서는 자동 흔들림 없이 직접 회전만 허용한다.

모바일에서는 가장 가까운 네 송이까지만 손길을 받으며, 움직일 때마다 꽃의 선을 새로 만들지 않는다. WebGL이 중단되면 같은 꽃 곡선과 회전을 Canvas로 투영한다. 자동 검사로 이 동작과 버퍼 한도를 확인했다. 실제 S24의 장시간 온도·전력 측정은 아직 하지 않았으므로 발열이 해결됐다고 단정하지 않는다.

## 돌아와도 남아 있는 하늘

끝났다는 큰 제목을 보여주기 전에, 하늘이 한 번 살짝 돌아 자신의 깊이를 드러낸다. 정면으로 돌아오면 작은 결과 요약과 조작부만 남는다. Touch와 Turn을 오가며 얼마든지 만질 수 있고, Share를 눌러야 이미지와 전달 방법이 열린다. 공유창을 닫아도 돌려 보던 시점은 그대로다.

랜딩도 경험의 일부로 남겼다. 로고를 누르면 첫 초대 화면으로 돌아가고, Return to your sky로 방금 만든 하늘을 다시 연다. 진행 중에는 잠시 멈춰 돌아갈지 확인한다. 다른 휴식을 시작했다가 그만두어도 이전에 완성한 작품은 같은 페이지 안에 남아 있다. 새로고침을 넘어 저장하는 보관함은 아직 아니다.

마지막 확인에서는 짧게 닿았다 떨어지는 손길도 살폈다. 화면이 늦게 그려지면 첫 반응 전에 입력이 끝날 수 있었다. 이제 한 번의 손길은 첫 프레임까지 남고, 꽃이 가라앉은 뒤에는 다시 쉰다. 좁고 짧은 모바일 랜딩에서는 반복 문구를 덜어 방금 하늘로 돌아가는 버튼을 바로 볼 수 있게 했다.

## 다음 업데이트가 공개본까지 가도록

GitHub에 소스가 있다는 사실과 공개 사이트가 자동으로 바뀐다는 사실은 달랐다. 기존 Cloudflare Pages 프로젝트는 직접 업로드 방식이었고, 이번 앞선 개선도 인증을 갱신한 뒤 직접 게시했다.

이를 반복하지 않도록 GitHub Actions에 빌드 일치 확인, 동작 검사, 필요한 정적 파일만 업로드, 고정 배포의 파일·브라우저 검증과 공개 도메인 연결 확인을 묶었다. 배포는 검사에 통과한 `main` 커밋에서만 진행한다. 일지와 캡처만 바뀌면 불필요한 재배포는 하지 않는다. 토큰 연결 뒤 실제 GitHub push로 자동 배포까지 완료했다. GitHub 서버가 공개 도메인의 보안 확인 화면을 받는 경우는 검증 미완료로 표시하며, 고정 배포의 기능 검증과 구분한다. 공개 주소 자체도 로컬 브라우저에서 다시 확인했다. 실행 결과와 검증 범위는 [배포 운영 문서](../deployment.md)에 기록한다.

이번 업데이트의 중심에는 사용자와 도구가 여러 번 다시 살펴본 작은 경험이 있다. 문장 하나의 줄바꿈, 검게 보이던 점, 모바일 PNG의 비율, 종료 뒤에도 만지고 싶은 꽃이 다음 작업을 결정했다. Afterglow의 하늘은 그렇게 조금 더 오래 머물 수 있는 장소가 됐다.

## 그 하늘에 맞는 서명

라이브 하늘까지 바뀌고 나니 처음의 해와 수평선 로고도 다시 보였다. 새 심벌은 한 점에서 펼쳐지는 세 꽃잎과 작은 잔광이다. 화면에 생겨나는 선의 움직임을 간결하게 남겼다. 이름은 소문자 세리프 윤곽으로 바꾸고 글자 사이를 조정해, 랜딩의 제목과 같은 시각 언어를 쓰도록 했다.

이 서명은 헤더에서 끝나지 않는다. 저장 PNG, 파비콘, 홈 화면 아이콘, 링크 미리보기와 GitHub 표지까지 같은 원본을 사용한다. README도 지금의 경험을 먼저 보여주도록 다시 썼다. 최신 화면과 사용법을 읽은 뒤, 관심이 생기면 이 제작 일지와 지난 버전으로 이어질 수 있다.
